# Сайт ООО «Арт-Пак Плюс»

Статический сайт производителя упаковки из гофрокартона (gofrocarton.by).
Без фреймворков и сборщиков в рантайме: на хостинг выкладываются готовые
`.html`, `assets/css`, `assets/js`, `assets/img`.

## Страницы

| Файл                | Раздел меню        |
|---------------------|--------------------|
| `index.html`        | Главная            |
| `o-kompanii.html`   | О компании         |
| `produkciya.html`   | Продукция          |
| `uslugi.html`       | Услуги             |
| `oborudovanie.html` | Оборудование       |
| `korzina.html`      | Корзина            |

## Как править контент

Шапка, меню, контакты и подвал одинаковы на всех шести страницах. Чтобы они
не разъезжались, они лежат в одном месте — в `tools/build.py`, а содержимое
страниц — в `src/*.html`.

```
src/<страница>.html      ← текст и блоки конкретной страницы
tools/build.py           ← шапка, меню, подвал, телефоны, адрес, иконки
tools/products_data.py   ← каталог продукции: подгруппы и прайс
```

После правки пересоберите готовые страницы:

```sh
python3 tools/build.py
```

Скрипт возьмёт `src/*.html`, подставит каркас и перезапишет `.html` в корне.
**Готовые файлы в корне править не нужно** — следующая сборка их перезапишет.

### Телефоны, адрес, почта

Все контакты заданы один раз в начале `tools/build.py` (`PHONES`, `FAX`,
`EMAIL`, `ADDRESS`, `HOURS`, `UNP`). Изменили там — после пересборки они
обновятся в шапке, подвале и на всех страницах сразу.

В тексте страниц те же значения доступны как подстановки: `{{phones}}`,
`{{phone1}}`, `{{email}}`, `{{fax}}`, `{{address}}`, `{{hours}}`, `{{unp}}`,
`{{legal}}`, а иконки — как `{{icon:имя}}` (список имён — в словаре `ICONS`).

## Иллюстрации

Все изображения — SVG, сгенерированные скриптами: они мало весят, не мылятся
на любых экранах и выдержаны в одной стилистике.

```sh
python3 tools/generate_art.py       # фоны слайдера: assets/img/hero-1..3.svg
python3 tools/generate_products.py  # карточки каталога: assets/img/pr-*.svg
```

Виды гофрокартона (`pr-kb*.svg`) рисуются срезом: по длинной грани видна
волна гофры, по числу слоёв сразу читается двух-, трёх- или пятислойный лист.

Три фона слайдера сделаны в одной палитре и одном освещении, поэтому
смотрятся как серия, но показывают разные сюжеты:

1. коробки выезжают по рольгангу из открытых ворот контейнера;
2. погрузчик заводит паллету с гофротарой в фуру;
3. сотрудники и заказчик у готовой партии — контражур от ворот склада.

Слайды на главной меняются сами, кнопок перелистывания нет: полоски внизу —
только индикатор прогресса. Интервал задаётся константой `DUR`
в `assets/js/main.js`.

Если появятся фотографии с производства, их можно поставить вместо SVG:
достаточно заменить `src` у `<img>` внутри `.slide__bg` в `src/index.html`
и у `.prod__pic` в `src/produkciya.html`, затем пересобрать.

## Каталог продукции и прайс

Подгруппы товаров и их прайс лежат в `tools/products_data.py`. Из этого файла
собираются сразу два места:

* сетка карточек на `produkciya.html` (плейсхолдер `{{catalog}}` в `src/`);
* отдельная страница подгруппы `produkciya-<slug>.html` с таблицей цен.

Добавить позицию в прайс — дописать словарь в `rows` нужной категории:

```python
"rows": [
    {"photo": "pr-box4.svg", "name": "400×300×300 Т-22",
     "p1": "2,3", "p2": "1,8", "p3": "1,30"},
],
```

Ключи строк совпадают с `key` из набора колонок, указанного у категории
в `columns`. Наборов несколько, потому что прайс у подгрупп разный:

| Набор           | Где                       | Колонки                                   |
|-----------------|---------------------------|-------------------------------------------|
| `COLS_TIER`     | гофроящики, гофролотки    | тиражи 20–300 / 300–1000 / 1000+          |
| `COLS_PIZZA`    | коробки для пиццы         | тиражи 3000 / 5000 / 10 000 шт.           |
| `COLS_FLAT`     | одна цена за штуку        | «Цена без НДС»                            |
| `COLS_MATERIAL` | виды гофрокартона         | образец, вид, описание — без цен          |

Служебное в колонках: `no` нумерует строки сам, `photo` подставляет картинку
из `assets/img`, соседние колонки с одинаковым `group` уходят под общую шапку
(«Цена без НДС» с `colspan`), `nowrap` запрещает перенос в ячейке.

У категории можно задать ещё `note` (сноска под таблицей — доставка, условия
печати), `table_eyebrow` / `table_t` (заголовок блока с таблицей) и `sections`
— текстовые блоки внизу страницы: так на странице маркетплейсов сделаны
требования Wildberries и OZON.

Пока `rows` пустой, вместо таблицы выводится блок «Цена по запросу» с кнопкой
заявки: пустых таблиц и выдуманных цен на сайте не появляется.

На узких экранах таблица не скроллится вбок, а разбирается на карточки:
подписи колонок берутся из `data-label`, поэтому новые колонки работают
на мобильных сразу.

После правки — `python3 tools/build.py`. Список страниц подгрупп нигде не
дублируется: сборщик берёт его из `CATEGORIES`, а проверка адаптива —
с диска по маске `produkciya-*.html`.

## Корзина и заявка

Заказ собирается прямо в прайсе на странице подгруппы: «плюс» рядом с номером
позиции раскрывает окошко с тиражом, оттуда позиция улетает в корзину в шапке.

Цена подставляется по тиражу: у колонок прайса есть ключ `min` — с какого
тиража колонка действует, — и корзина берёт последнюю ступень, порог которой
уже пройден. Позиции без цены (виды гофрокартона) кнопки «в корзину» не
получают, потому что складывать в заказ там нечего.

Состав заказа лежит в `localStorage` под ключом `apk-cart`: сайт статический,
иначе между страницами его не передать. Оттуда же он подставляется в письмо,
поэтому в заявке остаются только имя, телефон, e-mail и комментарий — размеры
и тираж второй раз вводить не нужно.

Серверной части нет: форма на `korzina.html` проверяет поля и собирает письмо
на `info@gofrocarton.by`, открывая почтовую программу посетителя. Когда
появится бэкенд — достаточно заменить тело обработчика `submit`
в `assets/js/main.js` на `fetch()` к своему эндпоинту.

## Ширина макета

Контейнер всех секций — `.wrap`, его предел задаёт переменная `--wrap`
в `assets/css/style.css`. Она раскрывается ступенями, чтобы на большом
мониторе сайт не стоял узкой колонкой посреди пустого фона:

| Ширина экрана | `--wrap` | Поля по краям |
|---------------|----------|---------------|
| до 1439px     | 1280px   | по `--gut` (до 40px) |
| от 1440px     | 1560px   | 40px + остаток экрана |
| от 1920px     | 1760px   | 80px + 40px внутри контейнера |

Первый экран живёт по тем же правилам: `.hero__in` — это тот же `.wrap`,
поэтому заголовок героя, заголовки разделов и колонки подвала стоят на одной
вертикальной направляющей на любой ширине.

Вместе с контейнером в блоке «19b» стилей подтягиваются сетки, поля карточек
и типографика: на широком экране текст не должен мельчать вместе с ростом
свободного места (заголовки разделов 44–46px, абзацы 17–17.5px). Диапазон
до 1440px эти правила не задевают вовсе — телефоны и планшеты остаются
ровно такими, какими были.

Каталог продукции (`grid--cat` на `produkciya.html`) — единственная длинная
сетка: колонки в ней считает `auto-fit`, добавляя ещё одну, как только в ряд
помещается карточка не у́же 380px. Отсюда три широкие колонки на 1440–1900px
и четыре на Full HD. Нижняя граница в 380px нужна, чтобы карточка на большом
мониторе не оказалась мельче, чем была на ноутбуке. Сетки на три и шесть
карточек (главная, «Услуги», «О компании», «Оборудование») остаются
трёхколоночными: лишняя колонка оставила бы дыру в ряду.

## Проверки

```sh
npm install        # один раз, ставит playwright-core
npm run check      # обе проверки подряд
```

Или по отдельности: `npm run check:responsive` и `npm run check:functional`.
Есть и ярлыки для сборки: `npm run build` (страницы) и `npm run art`
(перегенерация всех SVG).

`responsive.js` прогоняет все страницы (шесть основных плюс страницы
подгрупп продукции) по ширинам от 320 до 2560 px (телефоны, планшеты,
ноутбуки, широкие мониторы) и падает, если вёрстка где-то вылезает
за экран. Отдельно взяты обе границы раскрытия контейнера — 1439/1440
и 1919/1920 px: именно на переходе легче всего получить лишний пиксель
по горизонтали. `functional.js` проверяет
интерактив: слайдер, фильтр каталога, аккордеон, корзину (тиражные цены,
перенос между страницами, правку и удаление позиций), валидацию формы
и мобильное меню, а также ширину макета на десктопе — ступени `--wrap`,
колонки каталога, размеры заголовков и абзацев на внутренних страницах
и то, что до 1440px ничего из этого не сработало.

Путь к Chromium берётся из `CHROME_PATH`, по умолчанию — из стандартного
каталога Playwright.

## Поддержка браузеров

Вёрстка на CSS Grid и Flexbox, скрипт — на ES5-совместимом синтаксисе с
`IntersectionObserver` (при его отсутствии блоки просто показываются сразу).
Учтён `prefers-reduced-motion`: анимации и автопрокрутка слайдера отключаются
для пользователей, которые их не хотят.
